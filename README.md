# ธรรมะ Auto — การ์ตูนธรรมะอัตโนมัติ

ระบบทำคลิปการ์ตูนธรรมะ 2D doodle อัตโนมัติ (หลักธรรม ชาดก พุทธประวัติ ธรรมะในชีวิตประจำวัน) ตั้งแต่หัวข้อจนถึงไฟล์ MP4
คัดลอกมาจาก "Youtube Free animation Auto Claude" แล้วเปลี่ยนเนื้อหาเป็นธรรมะ — ทำงานแยกจากตัวเดิม (พอร์ต 8785, ตัวเชื่อม Chrome `com.dhamma_auto.bridge`, extension คนละตัว) ใช้คู่กันได้
อ้างอิงกติกาทั้งหมดจาก `extension/VDO Concept.txt` (Blueprint V5 ธรรมะ — มีกฎ 9 เรื่องความถูกต้องและการวาดพระพุทธเจ้า/พระสงฆ์อย่างเคารพ) — อยู่ในโฟลเดอร์ extension เพื่อให้แผงข้างอ่านได้

## สร้างไฟล์ติดตั้งให้ลูกค้า (Setup.exe)

```powershell
node scripts/build-installer.mjs    # → dist/DhammaAuto-Setup-<version>.exe (~150MB)
```

ไฟล์เดียวมีครบ: โปรแกรม + Node + ffmpeg + Python/เสียง Edge · ไม่มี Chrome ตัวติดตั้งโหลดให้ · ระบบเสียงในเครื่องเป็นตัวเลือก (โชว์เฉพาะเครื่องที่มีการ์ดจอ NVIDIA)
ไม่ติด API key / เสียงที่โคลน / งานคลิปของเรา (ตรวจทุกครั้งก่อนสร้าง) · เลขรุ่นมาจาก `extension/manifest.json` — อัปเดตให้ลูกค้า: เพิ่มเลขรุ่นแล้วสร้างใหม่ ลูกค้ารันทับได้ งานไม่หาย
ต้องมี Inno Setup 6 (`winget install --id JRSoftware.InnoSetup -e --scope user`) · สคริปต์ตัวติดตั้ง: `installer/DhammaAuto.iss`

## ติดตั้ง (เครื่องใหม่)

ต้องมี: Windows · Chrome ที่ล็อกอิน ChatGPT และ Google Flow ไว้ · [Node.js](https://nodejs.org) · ffmpeg (`winget install Gyan.FFmpeg`)
ถ้าเปิดแอนิเมชันในตั้งค่าม้าน้ำ ให้กรอก Kie API key (มีค่าใช้จ่ายตามจำนวนฉาก) ไม่ต้องล็อกอิน Meta AI
ถ้าจะใช้เสียงในเครื่อง (เสียงไทย F5-TTS, เทรนเสียงตัวเอง, ถอดเสียง Whisper): การ์ดจอ NVIDIA + Python 3.10

1. ดับเบิลคลิก `ติดตั้งครั้งแรก.bat` — ลงตัวเชื่อม Chrome และถามว่าจะลงระบบเสียง (`tts\.venv` ~5GB) เลยไหม
2. Chrome → `chrome://extensions` → เปิด Developer mode → Load unpacked → เลือกโฟลเดอร์ `extension`
3. ปิดเปิด Chrome แล้วกดไอคอน ธรรมะ Auto

ทุกอย่างอยู่ในโฟลเดอร์นี้โฟลเดอร์เดียว ไม่ต้องมีโปรเจกต์อื่น · เสียงที่เทรนไว้อยู่ใน `tts/voices/<ชื่อเสียง>/` (model.pt + คลิปต้นแบบ)
คัดลอกโฟลเดอร์เสียงไปเครื่องอื่นได้ตรงๆ · เสียงส่วนตัวไม่ถูกแชร์ไปกับ git (`.gitignore`) — คนอื่นใช้เสียง Edge ได้ทันที หรือเทรนเสียงตัวเองในขั้นที่ 3

พิมพ์หัวข้อ เลือกภาษาและความยาว กด **▶ ทำคลิปอัตโนมัติ** — ทำงานเป็นแผนกต่อกันจนได้ MP4:

| แผนก | ใช้ | ถ้าพลาด |
| --- | --- | --- |
| เขียนบท | ChatGPT | ลองใหม่ 3 ครั้ง, บทยาวผิดเป้ามากขอเขียนใหม่ |
| เสียงพากย์ | เสียงที่เลือกในขั้นที่ 3 | ลองใหม่ |
| กำกับภาพ | ChatGPT (Style/Character Bible + prompt ทีละ 40 ช็อต) | ขอช็อตที่ขาดต่อจนครบ |
| วาดภาพ | Google Flow Agent · Nano Banana 2 Lite · 0 credits | สั่งเฉพาะช็อตที่ขาดต่อจนครบ, หยุดเมื่อไม่ได้ภาพเพิ่ม 3 รอบติด |

เสร็จแล้วมีหน้าต่างสำเร็จ + แจ้งเตือนบนเครื่อง (แม้ปิดแผงข้าง) · หยุดกลางทาง → กดอีกครั้งด้วยหัวข้อเดิม ทำต่อจากแผนกที่ค้าง
ใน **ตั้งค่าม้าน้ำ · Kie API** ปิดแอนิเมชันเพื่อใช้ภาพนิ่งตัดต่อ หรือเปิดและเลือก 20% / 60% / 80% / 100% ของฉากทั้งเรื่อง โมเดลเริ่มต้น (ระดับถูก) คือ Seedance v1 Pro ภาพ→วิดีโอ 480p/5 วินาที 14 เครดิต ($0.07) ต่อฉาก วัดจากงานจริง ต.ค. 2026 · สำรองด้วย Seedance 2.0 Mini (หักจริง 19 เครดิต) · Seedance 1.5 Pro ถูกปลดจาก Kie แล้ว (ตรวจราคาจริงก่อนใช้งาน) กรอก key ในแผงข้างซึ่งเก็บใน `.env` ของเครื่องและไม่ส่งไปส่วนขยาย
คำสั่งเดียวกันจาก terminal: `node pipeline/autopilot.mjs "หัวข้อ" --lang th --minutes 5`

## ทำทีละขั้นในแผงข้าง

1. **หัวข้อ + บทพากย์** — แผงสั่ง ChatGPT แล้วดึงคำตอบกลับมาเอง
2. **เสียง ภาพ วิดีโอ** — โปรแกรมในเครื่องเปิดเองและหยิบบทที่เขียนไว้ไปทำต่อ

ChatGPT / Google Flow ทำผ่านหน้าเว็บ ส่วนม้าน้ำใช้ Kie API เฉพาะเมื่อเปิดแอนิเมชัน; งานตัดต่อและเสียงในเครื่องทำภายในเครื่อง

## Pipeline

```
1_script    หัวข้อ + VO script        → 01_script/script_<slug>.txt
2_tts       script → เสียงพากย์       → 02_audio/voiceover.wav + durations.json
3_timecode  ความยาวจริง → timecode    → 03_timecode/*.{json,txt,srt} + 04_shotlist/slots.json
4_shotlist  slots → OUTPUT 5 ครบ      → 04_shotlist/agent_brief.txt
5_images    shot list → ภาพ           → 05_images/00_00_05.png ...
6_render    ภาพ + เสียง → MP4         → 06_render/<slug>.mp4
```

แต่ละขั้นอ่าน/เขียนไฟล์ล้วน ไม่มี state ในหน่วยความจำ → รันซ้ำขั้นไหนก็ได้โดยไม่ต้องเริ่มใหม่

## เลือกภาษา (ไทย / อังกฤษ)

ชื่อเรื่องกับ narration แยกภาษากันได้ — คู่ที่ใช้บ่อยคือชื่ออังกฤษ (ติด search) narration ไทย

ตั้งถาวรใน `config/project.config.json`:

```json
"language": "th",        // narration ที่จะเอาไปพากย์
"titleLanguage": "en"    // ชื่อเรื่องและหัวข้อ
```

หรือสั่งเฉพาะครั้งด้วย flag:

```powershell
node pipeline/1_script.mjs topics --title-lang th
node pipeline/1_script.mjs script 3 --lang en --minutes 12
```

ภาษาถูกบันทึกลง `01_script/meta.json` เพื่อให้ขั้นที่ 2 เลือก TTS engine ให้ถูก
(engine ไทย `f5-tts-thai` / อังกฤษ `chatterbox` — ถ้าตั้งไม่เข้าคู่กัน ขั้นที่ 2 จะเตือนก่อน gen)

## โพสต์ TikTok ผ่าน Chrome

TikTok ใช้บัญชีที่ล็อกอินใน Chrome เดียวกับส่วนขยาย ไม่ใช้ TikTok API ไม่เก็บรหัสผ่านหรือคุกกี้ลงโปรแกรม

1. อัปเดตส่วนขยายเป็น 1.0.14 ขึ้นไป และอนุญาตการเข้าถึง `www.tiktok.com` หาก Chrome แจ้งขอสิทธิ์ใหม่
2. เปิด **โพสต์อัตโนมัติ → ตั้งค่า → TikTok → เปิด TikTok Studio** แล้วล็อกอินบัญชีที่ต้องการ
3. กด **เชื่อมบัญชีที่ล็อกอินใน Chrome** ตรวจชื่อ `@username` ที่แสดง บัญชีใหม่เริ่มการมองเห็น **เฉพาะฉัน**; เลือก **สาธารณะ** หรือ **เพื่อน** ได้ในส่วนเดียวกัน
4. ตั้งหมวดที่บัญชีรับ เลือกบัญชี TikTok เป็นปลายทางของคลิป แล้วอนุมัติ/ตั้งเวลาเหมือน Facebook และ YouTube เปิดเครื่องและ Chrome ไว้เมื่อถึงเวลา

ป้ายกำกับเนื้อหาที่สร้างด้วย AI เปิดไว้เป็นค่าเริ่มต้นสำหรับคลิปที่โปรแกรมสร้าง ตัวขับตรวจบัญชี คำบรรยาย การมองเห็น และป้าย AI ก่อนกดโพสต์ หากหน้าเว็บเปลี่ยนจนหาองค์ประกอบไม่เจอ ระบบหยุดพร้อมแจ้งเหตุผล

จำบัญชีได้หลายบัญชี แต่โพสต์ได้เฉพาะบัญชีที่ล็อกอินอยู่จริง หากชื่อไม่ตรงให้สลับบัญชีใน TikTok ก่อนลองใหม่ หากพบ CAPTCHA ให้ผู้ใช้ยืนยันใน TikTok เอง

หากโปรแกรม/Chrome หยุดหลังเริ่มโพสต์ ผลอาจไม่แน่นอน: ระบบระงับปลายทางนั้นเพื่อป้องกันส่งซ้ำ และไม่มีปุ่มยืนยันข้ามการป้องกันนี้ อัปโหลดครบ 100% ยังไม่นับว่าโพสต์สำเร็จ ต้องพบผลยืนยันการเผยแพร่

การตรวจโค้ดใช้คิวชั่วคราว, bridge HTTP จริงบนพอร์ตทดสอบ และ DOM จำลอง รุ่น 1.0.18 รองรับการยืนยันป้าย AI ครั้งแรก, Show more และสวิตช์ AI ที่ไม่มีชื่อกำกับใน TikTok Studio โดยจับจากแถวการตั้งค่า AI โดยตรง หากโพสต์ไม่สำเร็จจะเก็บข้อมูลโครงสร้างตัวเลือกที่เห็นเพื่อวิเคราะห์ และตรวจแท็บที่เปิดค้างได้โดยไม่โหลดฟอร์มใหม่ ทดสอบครบตั้งแต่อัปโหลด ใส่คำบรรยาย เปิดป้าย AI และโพสต์คลิป 5 วินาทีแบบเฉพาะฉันบนเครื่อง SSH แล้ว TikTok ส่งผลยืนยันสำเร็จ และหน้า Studio แสดงคลิปเป็น Only me โดยสถานะการตรวจเนื้อหาของ TikTok เป็นขั้นตอนแยกหลังรับโพสต์

## โพสต์หลายแพลตฟอร์มและป้องกันส่งซ้ำ

รุ่น 1.0.19 ส่ง Facebook, YouTube และ TikTok ในรอบเวลาเดียวกันได้ โดยแต่ละแพลตฟอร์มทำงานแยกกัน ปลายทางที่สำเร็จแล้วจะถูกข้ามเสมอ ส่วนช่อง YouTube ต้องเชื่อมต่อก่อนจึงส่งได้

ประวัติถาวรอยู่ใน `projects/_posting/deliveries.json` แยกจากรายการคิว ตรวจทั้งเนื้อหาไฟล์ SHA-256, ไฟล์ต้นทาง และบัญชีปลายทางจริง จึงยังจำได้เมื่อลบแล้วเพิ่มคลิปเดิมกลับ เปลี่ยนชื่อไฟล์ หรือเชื่อมเพจเดิมใหม่ การส่งใช้ไฟล์สำเนาสำหรับรอบนั้น เพื่อไม่ให้ไฟล์ที่เรนเดอร์ทับระหว่างทางเปลี่ยนคลิปที่กำลังส่ง

ก่อนเรียกปลายทางต้องบันทึกการจองส่งลงดิสก์ และบันทึกผลสำเร็จก่อนปรับผลในคิว หากเน็ตหลุดหรือไม่รู้ผลหลังส่ง จะระงับปลายทางนั้น ส่วนความผิดพลาดที่ยืนยันว่าเกิดก่อนส่งยังลองใหม่ได้ ประวัติที่อ่านไม่ได้หรือหายไปหลังเริ่มใช้งานทำให้หยุดส่ง และการลบรายการคิวไม่ลบประวัตินี้ สำหรับ TikTok ที่ไม่มีรหัสผู้ใช้ถาวร การเปลี่ยนไปชื่อบัญชีอื่นจะไม่ทำให้คลิปเดิมถูกส่งซ้ำผ่านการตรวจประวัติ

## สลับบัญชี Google Flow

รุ่น 1.0.24 แบ่งงานภาพเป็นชุดละไม่เกิน 10 ภาพ (เช่น 26 ภาพ = 10 + 10 + 6) เพื่อไม่เกินจำนวนภาพต่อคำสั่งที่ Flow รองรับ ใช้โปรเจกต์และภาพอ้างอิงเดิมต่อเนื่อง นับเฉพาะภาพตามรายชื่อที่บันทึกกลับมาแล้ว ไม่รวมรูปอ้างอิงหรือข้อความที่ Agent บอกว่าสร้างเสร็จ

รุ่น 1.0.25 ปรับหน้า **ตั้งเวลาผลิต** ให้เลือก 3 เรื่องหลัก: เริ่มตอนนี้ / ตั้งเวลาครั้งเดียว / ทุกวัน, จำนวนคลิป (หรือเลือกทำต่อเนื่องจนกดหยุด), และพักหลังคลิปเสร็จ (ไม่พัก / เท่ากันทุกครั้ง / สุ่มช่วงเวลา) มีประโยคสรุปก่อนเริ่ม และบันทึกค่าให้อัตโนมัติ การสุ่มเนื้อหาและส่งเข้าคิวโพสต์อยู่ใน “ตัวเลือกเพิ่มเติม” เวลาเริ่มผลิตแยกจากเวลาโพสต์ในหน้าโพสต์อัตโนมัติ ค่าที่เคยตั้งไว้ยังใช้ได้เหมือนเดิม

รุ่น 1.0.29 กรอกคำบรรยาย TikTok ผ่านการป้อนข้อความของเบราว์เซอร์ แทนการเปลี่ยนโหนดในช่องที่ React ควบคุมโดยตรง เพื่อหลีกเลี่ยงหน้าอัปโหลดล้มหลังกรอกข้อความ คำบรรยายผูกกับงานที่กำลังส่งและแท็บเดิม พร้อมอ่านกลับเพื่อตรวจความตรงก่อนตั้งค่าและโพสต์ ระบบป้องกันโพสต์ซ้ำยังใช้ประวัติถาวรเดิม

ตั้งแต่รุ่น 1.0.21 เมื่อ Flow แจ้งชัดว่าบัญชีติดลิมิต ระบบบันทึกภาพที่ได้แล้ว สลับไปบัญชี Google ถัดไปที่ล็อกอินใน Chrome และทำต่อเฉพาะภาพที่ขาด โดยตรวจอีเมลบัญชีใหม่ก่อนส่ง prompt ทุกครั้ง บัญชีที่ติดลิมิตจะถูกพักตามเวลาที่ Flow แจ้ง (ถ้าไม่แจ้ง ใช้ 24 ชั่วโมง) แล้วกลับมาอยู่ในลำดับได้ เมื่อทุกบัญชีติดลิมิต ระบบหยุดรอและเก็บงานเดิมไว้ ไม่สลับวน ส่วนข้อความ high demand ยังใช้การรอคิวตามเดิม ระบบไม่กรอกรหัสผ่านหรือผ่านหน้ายืนยันตัวตนให้อัตโนมัติ

รุ่น 1.0.20 ใช้แท็บ Flow ที่เลือกล่าสุด แทนการกลับไปแท็บที่จำไว้ เมื่อบัญชีเดิมเต็มลิมิต ให้เปิดหน้าแรก Flow ในบัญชีใหม่ไว้ แล้วกด **ทำต่อ** ระบบจะไม่เปิดโปรเจกต์ของบัญชีเก่าทับ และจะเก็บตัวเลือกบัญชีใน URL ไว้เมื่อเปิดหน้าแรกสำหรับคลิปใหม่

ถ้าแท็บที่เลือกเปิดโปรเจกต์คนละคลิปอยู่ ระบบหยุดให้กลับหน้าแรกของบัญชีที่ต้องการก่อน เพื่อไม่ดึงภาพเก่าหรือเปลี่ยนชื่อโปรเจกต์อื่น เมื่อเปลี่ยนโปรเจกต์จะล้างรายการภาพที่จำไว้ และหน้าที่ถูก Chrome แปลจะหยุดให้ปิดการแปลแทนโหลด URL เก่าทับบัญชีที่เลือก
